# 0.15.1：Android 16 拖拽入口安装失败修复

日期：2026-11-03（Asia/Shanghai）。版本：0.15.1／33。本次按 [scope.md](scope.md) 读取用户提供的 LSPosed 归档并修复，未整体解压、安装手机或远程发布。输出为本地长期密钥签名候选。

## 日志结论

`log/modules_2026-11-03T09:50:35.166754.log` 第 15 行确认系统加载 `0.15.0/32`；第 56 行为 `drag stage=unavailable exception=NoSuchFieldException`，说明系统拖拽入口根本没有安装成功。第 172 行随后出现 `runtime channel ready`，宿主第 489、655 行均出现 `Drag native content/actions installed`；不能把通道或宿主就绪当作系统拖拽入口已经可用。

归档属性显示 Android 16、SDK 36、HyperOS 3.0。旧版固定读取 `DragState.mDisplayContent`，但固定提交 `frameworks/base@99b01a65cc4c104933788b3143285ab6bae65827`（`android-16.0.0_r1`）的官方实现已拆为 `mStartDragDisplayContent` 与 `mCurrentDisplayContent`。旧解析在该标准结构上会抛缺字段异常。

旧日志没有记录成员名，因此不能仅凭这份归档证明定制 ROM 缺少的具体字段。已确认的是入口安装失败；Android 16 字段兼容缺口由固定源码和反射回归复现。本地没有提取手机的实际 framework，也没有真机复测。

## 修复

- 优先使用当前／起始显示器的双字段结构，旧版单字段结构仍可用；缺少必要字段或类型不符时明确拒绝。
- 起始和当前显示器都必须为主显示器，保留原用户、token、UID、锁屏和来源范围校验。
- 新增与真实安装解析器相同的反射字段测试，覆盖旧结构、新结构、字段优先级、缺字段／错误类型和跨显示器拒绝。0.15.0 的原测试未覆盖这一层字段解析。
- 安装日志记录 `display_layout=split/legacy`；失败记录固定的 `contract_stage/member`。真实回调记录 `observed global/accepted`，后续拒绝输出固定 reason，均不记录正文、图片、链接或 ClipData 内容。
- 对只能同应用交付的拖拽和不支持的内容类型提前拒绝，避免拉起无法接收数据的空面板。

生产逻辑改动集中在 `drag/SystemDragHooks.java`，不新增来源应用 Hook 或自动点击。

## 安装后复核

1. 覆盖安装 `TaplusBridge-0.15.1-release.apk`。
2. 重启手机，让 system_server 使用新模块。
3. 打开模块，确认拖拽开启并点击保存，等待新版本配置同步。
4. 从支持原生全局拖拽的内容发起拖动。应先看到 `drag stage=installed ... display_layout=split`，实际拖动时再有 `observed`、`shown` 或具体 `rejected reason`。

若只有安装成功而始终没有 `observed`，不能据此声称来源已经发起系统全局拖拽；普通长按菜单仍不等于原生拖拽。未传出的卡片隐藏网址仍不能从标题推断。
