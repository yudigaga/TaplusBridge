日期：2026-11-13（Asia/Shanghai）。本地候选版本：0.15.45 / 77，包含上一候选 0.15.44 / 76 的弹层和取链仲裁修复。

用户要求覆盖评论区、帖子详情和信息流帖子卡片，范围不限酷安，并已澄清截图用于举例页面分类，不是在报告图中存在故障。目标是长按具体链接文字或链接卡片，提取该入口的真实地址。本轮按相同的物理触点、来源窗口与真实链接数据处理这三种位置，不以应用名、页面标题或“查看链接”文字定位目标。

归档 SHA-256 为 `5ac759dd7157f4835b55f3639a5a2c29a608e9cddcf885cb600a6f7e44b96031`。归档中 10:06:22、10:09:01 两轮 HTTP 捕获、导入后确有 Chrome Activity 启动；10:09:23 另一次启动被记为 `unsupported_action/unsupported_launch`，未记录其具体 action 和组件。不能把这三轮自动对应到示例图，更不能将第一轮通用修复说成日志中故障的已证原因。脱敏索引位于 `artifacts/diagnostics-20261113-103719/summary.json`。

| 证据 | 发现 | 修复路径 |
| --- | --- | --- |
| `AssistContentExtractor` 的触点节点优先级；新增父 href 回归在旧代码失败 | 卡片父节点具有显式 href，子标题只有文字时，更深的子标题会把实际目标丢掉 | 沿命中的同一条祖先路径保留最近的有界显式 href；子标题仍保留自己的文字 |
| `DragPayload.read()` 原先只把 `ClipData.Item.getText()` 写入文字缓冲；新增两项富文本回归失败 | 原生拖入仅包含带 URLSpan 的文字时，真实目标随纯文本转换丢失 | 只读取实际 URLSpan 的网址，沿用现有校验、数量、长度和通道限制 |
| 审查新增边界：可见 URL 与真实 href 不同、空图片子节点、重复长 span | 第一版补链会遗失真实父 href、丢父卡片正文，或在去重前耗尽缓冲 | 区分子节点显式链接与普通文本中的网址；空装饰节点不凭继承链接覆盖原文；重复 span 先去重后计入链接缓冲 |

以上是可由本地结构和 ClipData 样本复现的通用代码缺口，与截图是否展示故障分开记录。

## 三类页面的回归范围

| 场景 | 样本与预期 |
| --- | --- |
| 评论区 | 同屏主帖、所按评论、另一回复分别含不同目标；只保留所按评论的 URLSpan 目标 |
| 帖子详情 | 大配图、正文、链接入口共存；读取实际按中的链接节点，不把图片内显示的域名当作链接 |
| 信息流 | 长帖子卡片、滚动偏移和邻帖共存；按当前屏幕坐标获取对应子节点，不使用卡片中心或邻帖链接 |
| 标题式卡片 | 按中纯文字标题时保留所在有界卡片的真实 href；最近的嵌套卡片优先；子节点自己的 URLSpan/href 保留自己的目标 |
| 防止误取 | 不继承祖先正文里扫描出的其他网址，不继承全屏根节点 href，不采集兄弟内容；输入框、密码、blocked 节点仍排除 |
| 富文本原生拖入 | 隐藏 URLSpan 保留；可见网址与重复 span 去重；32 个相同 7 KiB URL 不得因重复累计而被拒绝 |

本轮不改变 Assist 多窗口歧义策略：若两个无法区分的窗口同时满足原始窗口边界和触点条件，返回空内容，不按列表顺序猜测。应用内 JS 或同 Activity 网页导航不保证产生可拦截的系统启动请求；未知 ClickableSpan 不会被执行来猜目标。
