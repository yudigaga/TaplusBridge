# 0.3.0-dev 无感识别卡片

日期：2026-10-29，Asia/Shanghai。

本版本按用户确认的不可见点击方案实现候选：在传送门点“无感识别此卡片”，系统确认探测能力后，内部触发原卡片点击，在支持的启动入口消费请求并取得网址，再将结果交回保留的传送门浮窗，生成真实目标应用名称和图标。用户不用再点微信原卡片，只有点击目标应用卡片后才打开或解冻目标。

这是新的行为实现，不再是0.2.2的只观察/放行模式。**新版本的实际输入投递、这张B站卡片是否无闪现、真实目标落点尚未真机确认。** 旧归档只证明原位置字段存在、0.2.2确认成功、原点击经过公共ATMS入口且rawUrl存在。

## 安装与使用

1. 覆盖安装[TaplusBridge-0.3.0-dev.apk](../artifacts/TaplusBridge-0.3.0-dev.apk)，versionCode 8，沿用原开发证书。
2. 保留“传送门 + 系统框架”勾选并重启，让system_server加载新版代码。不勾选微信或QQ。
3. 开启模块总开关、增强链接识别和“显示无感识别操作”。目标被冻结时，预先配置Root或冰箱授权；系统侧输入本身不通过Root命令执行。
4. 在默认屏竖屏环境长按原分享卡片，选择传送门中的“无感识别此卡片”。首版从这个明确操作触发，不在所有无URL消息上自动盲点，也不要求手动点原卡片。
5. 成功取得唯一可路由链接后，浮窗内出现“在哔哩哔哩打开”等目标应用卡片及图标；点击后再流转。无法定位、窗口遮挡、无唯一URL或不匹配当前域名规则时结束，不打开原网页。

探测输入之后设有约36秒的同来源已知网页保护/冷却，防止迟到请求或旧网址串入新探测。此期间再次探测会拒绝，同一来源的其他已知网页启动也可能暂时被阻止；目标应用卡片从传送门发起的启动不属于该来源UID。首版采取这项保守限制，不把它描述为只影响某个已确定URL的保护。

## 实际链路

### 宿主准备与内存回传

`RecognitionHooks`只在当次ContentCatcher Bundle有有效view_rect时允许探测，记录当次epoch、来源与时间；不能拿上一次长按的残留坐标。`HostProbeWindow`读取当前服务的来源Activity、首触点/注入点和范围，验证30秒时效、默认屏、竖屏及附着浮窗。优先使用落在范围内的first点，不能无条件使用双指中点。

对传送门自己的两个附着浮窗保存参数，必要时设置NOT_TOUCHABLE并清除WATCH_OUTSIDE_TOUCH，视觉内容不隐藏。高不透明覆盖窗或无法确定的窗口拒绝探测，不降低系统触摸保护，不伪造trusted标记。结束、取消、异常、旋转或窗口变化时恢复参数；READY后发TAP之前再次核对窗口快照。

新协议显式区分ARM和TAP，要求protocol=1、mode=invisible、block_ready=true及匹配nonce/user。旧版空ACK不能允许点击，未重启仍运行旧观察器时只会失败，不会主动点开网页。回调用真实框架ResultReceiver基类跨Parcel传输，保留此前匿名类解包问题的修复。

系统回传的URL只在Binder和进程内存在。宿主检查原epoch/source/nonce仍有效后调用既有预览和卡片生成逻辑，不执行cancelTask，不销毁浮窗，不在识别阶段自动启动目标应用。

### 源窗口命中与菜单

系统在WMS锁内只做本地窗口快照，验证原点下窗口的UID、用户、来源Activity、frame和真正主窗口对象，输入与Provider调用均在锁外。仅验证“同一个微信UID”不足以防止点到删除、收藏等菜单项。

只有明确属于同一Activity、parent为该主窗、当前焦点且可见的模态附属Popup，并且原卡片点严格在Popup frame外，才允许一次菜单外部DOWN→CANCEL。框架标准Popup在外部DOWN即关闭；CANCEL防止菜单恰好消失时第一轮变成完整卡片点击。随后必须重新命中原Activity真正主窗，才能执行最多一次实际卡片DOWN→UP。若第一轮已经触发受保护启动，则不再发第二次卡片点击。点落在菜单内、未知Dialog或无法确认的遮挡都拒绝；不发BACK键、不重试、不中途改变坐标。

InputManager事件指定来源UID与默认display，使用WAIT_FOR_FINISHED等待源处理，避免把“已排队”误当菜单已关闭。屏幕交互/锁屏、前台Activity、用户、display、尺寸和旋转在注入前核对。每个序列出现错误时发送CANCEL清理；没有非定向输入或CLI降级。

### 启动取消的位置

最终使用的是此前用户日志已命中的公开12参数`ActivityTaskManagerService.startActivityAsUser`入口：在本次事务匹配后，**不执行原方法体，向调用方返回外部成功0**。此时尚未创建ActivityStarter、ActivityRecord或方法体中的SafeActivityOptions；不属于在`ActivityStarter.execute()`内部伪造成功、跳过其finally清理的错误方式。可读取的ActivityOptions会显式通知取消。

这比设计记录中参考IceBridge的内层取消位置更早，目的相同：来源网页在创建前被消费，而不是打开后隐藏。只有未拥有的请求才调用原方法，且proceed位于恢复catch之外、不会被重放；已消费分支的错误不会触发protective回退放行原页面。无唯一URL、危险载荷、请求结果等不支持类型仍被消费并返回失败，不执行原网页回放。

身份绑定来源包、UID与Android用户；当前用户别名只对已验证来源身份规范化，不跨用户回传URL。结果与取消都绑定当前generation/nonce，旧会话和重复结果不能污染新卡片。URL只从已知微信/QQ网页组件的白名单字段中提取，限制深度、节点、长度和数量，歧义或读取异常时不返回部分结果。

### 目标应用打开

探测生成的卡片标为内存流转，点击时只按当前HTTP域名规则规划，去掉原浏览器和旧原生桌面候选，防止规则删除后退化为打开浏览器或目标首页。已启用且可解析的目标直接打开；需要解冻时使用有界、30秒、单次的内存票据进入已有透明入口。失败只结束，不提供原网页回退。

本次探测URL与这些内存票据不写SharedPreferences；进程重启后丢失并拒绝消费。普通识别仍保留原有短期持久化票据行为，不能把“探测不落盘”扩大解释成所有历史流转都不写URL。
