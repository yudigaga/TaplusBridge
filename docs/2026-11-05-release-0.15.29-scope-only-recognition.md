# 0.15.29 识别窗口与原点补点

日期：2026-11-05（Asia/Shanghai）。正式版本：0.15.29 / 61，本地长期签名 Release。沿用用户确认的 `system` 和 `com.miui.contentextension` 两个作用域。

## 本轮变化

- 删除关闭来源长按菜单时的屏幕角落事件。实际卡片补点保留最初物理 DOWN 的屏幕坐标，不换算密度、不按卡片中心猜点。菜单覆盖原点时明确终止补点；原点在菜单外的情形只在原点发送菜单关闭的 DOWN/CANCEL，再校验主窗。
- 普通识别和系统拖动的补点共用宿主浮窗透传握手。传送门先释放两类已知浮窗的触摸遮挡并等待窗口更新，再确认可以注入。握手绑定宿主 UID、随机 nonce、配置及输入代次；正常完成、拒绝或超时后恢复原窗口。新窗口或新参数不会被旧 lease 覆盖。
- 等待宿主失败或超时后，取消本轮启动拦截，继续交付已得到的实际正文；真实新 DOWN 使旧 ACK、内容及补点失效。
- 平台结构采集支持主窗口内唯一命中触点的实际 root，准确叠加 WindowNode 与 root 偏移，包括负偏移。不再把空结构回包算作识别成功。
- 扩大通用目的 URL 读取：同来源显式页面和自定义 Action 可读取明确目的字段中的唯一实际网址，跳过 referrer、统计和图片字段；歧义、多链接继续拒绝，没有增加逐应用适配。
- 增加注入点回读比较。后续日志可区分 `point_confirmed` 和 `point_mismatch`，不保存原坐标、网址、正文或 nonce。该回读只能比较请求点与输入监视器回读点，不能证明源页面中的卡片没有移动。

## 兼容边界

HyperPortal AES 的真实 View/Compose 取数依赖源进程，本轮没有新增来源作用域。平台不给结构、结构为空、自绘页面、无法观察到 URL 的页内跳转、来源菜单盖住原点等场景仍可能没有链接，不能据此宣称全覆盖。输入日志缺少原始坐标，不能把静态发现当作用户每次偏位的确定根因。

安装后保持系统和传送门作用域，并重启使 system_server 和宿主 Hook 更新，再复测长按识别、拖动及卡片不同屏幕位置的补点。
