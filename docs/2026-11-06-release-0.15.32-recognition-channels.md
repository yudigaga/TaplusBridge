# 0.15.32 独立识别开关与链接来源

日期：2026-11-06（Asia/Shanghai）。版本：0.15.32 / 64，长期签名 Release，保持系统与传送门两个作用域。

## 本轮修正

0.15.31 的补点采用页面草稿：切换只改变显示，未点击保存时持久值仍开启；页面导航不提交，恢复前台同步的仍是旧值。因此即使界面看似关闭，日志也会记录 stored/confirmed=on。这是本轮实际复现的交互缺口，不继续以远程发布失败猜测解释最新日志。

识别相关开关现为点击立即提交、回读并发布，失败显示错误。补点不再属于手势草稿，截图兜底也不属于应用名单草稿；手势保存/放弃及应用名单保存都不会回写这些即时开关。已覆盖实际thumb触摸、导航与Activity重建。

## 开关

在“手势”页分别提供：

| 开关 | 能力 |
|---|---|
| 原生文字与卡片 | 原生长按回调中的实际正文与卡片元数据 |
| 页面结构采集 | 触点附近Assist结构正文与链接，不点击来源 |
| 图片文字OCR | 已有图片本地或云端OCR正文与网址 |
| 服务端推荐识别 | 传送门推荐请求及返回卡片，包括剪贴板电商推荐 |
| 文字分词处理 | 对已有正文分词，不作为独立取链来源 |
| 剪贴板识别 | 传送门收到的剪贴板输入 |
| 截图采集兜底 | 模块原生取数不足时采集图片；OCR另行控制 |
| 不可见点击取链 | 松手后点击最初位置并截获实际启动链接 |
| Google Lens识图 | 现有Google图片识别入口，沿用原配置 |

新增六通道默认兼容开启，截图及补点沿用原值、缺省关闭。原有增强链接识别仍为总开关；原生链接接管为打开行为，不等于原生来源采集开关。各源通过schema6完整快照和宿主认证路由传递，旧schema1–5兼容，损坏通道配置关闭来源。

## 隔离与观察

取消在推荐/分词入口重复抓取同一原文；原生关闭时在宿主消费前过滤原文，拖动直接payload及外部ClipData也不能重新带回原生URL。Assist和补点正文分开处理，已有taplus_drag转发不会伪记成新的来源。OCR请求、回调、TalkBack旁路、剪贴板电商请求及晚到回包均增加门控。模块未激活或配置不可读时不主动截断宿主原有流程。

关闭分词不会跳过图片OCR，也不会把OCR纯文字丢掉；本地/云OCR正文按当前会话保留，上限128KiB。拖动完成等待同一会话的OCR及仍开启的SERVER任务。

固定日志 `recognition source stage=links channel=... found=... added=... total=...` 区分native/assist/ocr/server/clipboard/probe。found为本次输入真实提取量，added为本轮新入库量，total为本轮累计；重复来源可出现added=0。来源最多32条事件、每次数量不超过8，不保存正文、完整URL、nonce或坐标。空结果保留原阶段诊断，不伪造来源成功。

建议观察时先关闭“不可见点击取链”，再只开启要比较的来源，等系统确认后重新长按。截图采集不是OCR处理本身；测试图片OCR时按场景保留原生图片或截图兜底。分词不是链接获取渠道。当前已采集的链接不会在切换时按来源回溯删除，因此使用新一轮手势比较。

不可见点击开启时保留现有兜底时序，不保证所有已启用识别都先于点击完成。部分宿主能力边界为可选Hook，缺失时日志会说明；真实ROM行为仍需设备验证。
