# 弹窗取消的手势阶段边界

日期：2026-11-14。本地修复候选：0.15.51 / 83。

按本次用户要求，来源应用本轮新弹窗的关闭，只能发生在模块长按识别阶段或后续长按拖动阶段到达后。系统原生长按阶段不关闭；识别阶段之前已经松手的手势不能在之后补发关闭。三段手势的配置时长不变。

## 根因与修正

原 `SystemScopeCapture` 把系统原生长按到期时刻同时用于菜单候选和有效松手门槛；原生识别界面较早显示时，就可能在模块识别阶段之前发出关闭。

现在分离两个时刻：`nativeAt` 继续校验本轮界面通知的归属，`recognitionAt` 控制何时允许执行关闭。提前到达的可见通知被保留，记录的 `shownElapsed` 仍是首次实际显示时间，不伪造为识别阶段时刻。只有真正到达识别阶段，才开始原有 1.5 秒菜单观察窗口；拖动阶段继续沿用，不新增时间或独立关闭入口。

系统阶段的 UP 会撤销候选。释放有效性使用 UP 事件发生时刻，而非 worker 处理时刻，避免事件积压后被误认为按到了识别阶段。另将 `SystemProbe` 普通与已转移的真实输入统一记录：先采 elapsed、后采 uptime，以 `elapsed - max(0, uptime - eventTime)` 换算真实释放时间，防止输入接收延迟和时钟采样间隔延长持按。

保留原有物理流身份、最终触点校验、新输入／按键撤销、配置身份、同源 Activity／窗口／surface、DOWN 时窗口基线、独立 Back 回调与单次识别任务保留凭证。没有增加模拟返回或盲点点击，没有放宽长按前已有弹窗的边界。系统原生拖拽的隔离和已经转移的触摸流处理保持原结构。

## 回归证据

系统集成 fixture 使用 100 / 200 / 300 毫秒分别代表系统长按、模块识别、拖动阶段。新增五项用例：

- 101 毫秒提前显示，199 毫秒不关闭，恰好 200 毫秒才关闭。
- 系统阶段 149 毫秒松手，201 毫秒晚到通知不能关闭。
- 199 毫秒松手先入队，201 毫秒处理时不能关闭。
- 199 毫秒物理松手，201 毫秒先处理阶段回调、再交付原 UP，也不能关闭。
- 首次显示发生在拖动阶段 300 毫秒时，允许按原安全检查关闭。

旧实现 11 项集成检查出现 4 项预期失败，日志在工作区 `analysis/popup-stage-20261114/stage-red.log`。阶段修复后，控制器与系统集成通过；真实已安装 Pointer Hook 的晚 UP 回归又复现独立时间记录错误：34 项中仅该项失败，见 `timing-red.log`。统一真实输入时间后，扩大范围的定向检查通过。

控制器还覆盖首次显示时间保留、超过 1.5 秒的阶段等待不耗观察期、早期撤销不能复活；既有 Overlay 菜单回声、真实返回键、窗口基线和配置撤销测试继续保留。独立审阅未发现剩余阻塞项；提出的时钟采样顺序已一并修正。
