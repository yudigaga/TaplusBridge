日期：2026-11-02，Asia/Shanghai。普通模块功能与故障分析，`flavor=null`。用户授权见 [scope.md](scope.md)。

## 结果和使用

0.13.0 / 24 将正常流程改为：点击「识图」自动提交当前图片 → 后台读取 Google Lens 真实结果 → 同一传送门面板显示原生列表。正常流程不再要求点上传按钮或选择同一图片，不自动打开 Activity 或浏览器。

点击结果条目，在面板内的网页区域浏览来源网站；「返回结果」销毁该网页组件并恢复缓存的原生列表和滚动位置。右上角「原网页」始终指向本次 Lens 完整搜索页，由用户点击后才用外部浏览器打开；没有真实搜索网址时禁用，不用首页或虚构网址替代。换图、关闭、新请求使旧网址和旧回调失效。

覆盖安装 `artifacts/TaplusBridge-0.13.0-release.apk` 后重启，确认模块首页版本；LSPosed 仍保持传送门和系统框架作用域，Google Lens 开关开启，模块本体未被冻结。用户需能访问 Google。

## 实现

- 手机模块普通进程内，以 HttpURLConnection 提交真实 multipart 图片，字段 `encoded_image`，接入当前 Chromium 的 Lens 上传地址和已确认参数；不经过文件选择器、图床或自建服务。
- 图片仍使用当前宿主 Bitmap 的有界后台编码及 FD 交接，校验 SHA-256、格式和尺寸；不重新截取聊天界面，不回收宿主 Bitmap。
- HTTP 请求和工作进程 WebView 使用同一实际引擎版本的桌面兼容 User-Agent，并同步自身 Cookie。返回 Cookie 应用完成后才继续重定向；不读取或复制 Chrome/Google App 的登录 Cookie。
- 严格限制 Google HTTPS 重定向、响应大小和超时。跨域 307/308 不重发图片。HTTP 返回搜索 GET 地址记作 `navigation_ready`，随后由 WebView 实际加载；该阶段不算识图成功。
- 已观察的桌面卡片解析规则保留，不新增未经观察的手机类名或假结果。明确 JSON.stringify 协议；错误增加固定原因码、文档状态和选择器计数，不记录正文、图片、Cookie 或完整地址。解析失败保留本次真实原网页入口。
- 正常任务不创建前台上传页面。只在实际 Google 确认、账户或验证码文档被识别后提供「处理 Google 验证」，不由 HTTP 403/429 独自推断登录要求，也不自动拉起。
- 原生结果区新增「原网页」，只携带本次 URL、仅发送给浏览器包；多浏览器且无明确默认时才显示浏览器选择。来源网页只在用户点击条目后创建面板内平台 WebView，不向其暴露模块桥接、本地文件、相机等能力，不自动跳应用或绕过 TLS。

面板内网页依赖宿主普通应用 UID；实际日志为 10123。对不支持 WebView 的进程环境返回明确错误，不擅自跳出面板。换图、关闭、返回结果都销毁网页，恢复缓存列表，不重新上传。
