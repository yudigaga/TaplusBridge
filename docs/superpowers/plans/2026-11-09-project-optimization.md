# 全项目可靠性与响应优化实施计划

> 执行方式：使用 subagent-driven-development 按文件边界分工；主代理统一运行 Gradle，完成后独立审阅。

**Goal:** 执行用户认可的九项审阅建议，修复保存一致性与任务生命周期问题，降低输入、识图和设置页的重复工作。

**Architecture:** 保留现有 Provider、系统手势、宿主 Hook 与模块 UI 的职责。只在必要处增加提交边界、请求代次或有限寿命资源，复用现有线程、取消和验证机制。所有异步结果在提交前重新检查所属任务与配置。

**Tech Stack:** Android Java/Kotlin、libxposed API 102、Compose/Miuix、Robolectric/JUnit、Python unittest。

**Spec:** 本会话 2026-11-09 的九项审阅建议，以及用户“按计划执行”的授权。

## 约束与审阅重点

- 保留本会话已经完成、尚未提交的长按优化；保留无关本地文件。
- 保留应用范围、补点授权、主用户/窗口检查、旧结果隔离、正在获取的链接等待和用户手势阶段设置。
- 保存失败不能把被拒绝的设置发布为活动配置；提交过程不能被另一个同步任务读到中间状态。
- 图片管道读写必须有总时限，取消能解除阻塞；不可在宿主/系统手势锁内做阻塞 I/O。
- 合并移动时保留终止事件和多指变化的顺序，不补发已取消/旧手势的输入。
- Lens 会话/页面替换不能删除新图或占住新页面的下载队列；取消和超时释放连接。
- 应用列表缓存须在安装、卸载、更新及可见状态变化后失效；旧扫描不得覆盖新结果。
- 本次只做本地验证和候选构建，不安装设备、不远程提交发布、不递增正式版本。
