# 0.2.0-dev 单次卡片捕获验证

日期：2026-10-29，Asia/Shanghai。

> 本文为0.2.0的历史记录。该包将框架作用域误写为`android`，本文下方“安卓系统”的勾选说明有误。请使用0.2.1并勾选`system`（系统框架），当前操作与验证结果见[作用域修复说明](2026-10-29-system-scope-fix-0.2.1.md)。以下保留旧版本事实，不能作为正确注入框架的证据。

本版本落实已确认方案的第一阶段：从传送门主动布防，在系统启动边界验证原卡片是否暴露网址。**观察结果尚未用于拦截、解冻或改道；原卡片仍按原方式打开。** 它不能被描述为微信卡片、折叠消息或无中间页面跳转已经修复。

## 安装和复现

1. 安装 [TaplusBridge-0.2.0-dev.apk](../artifacts/TaplusBridge-0.2.0-dev.apk)，版本为0.2.0-dev / versionCode 5，Android Debug签名，可覆盖同签名开发版。
2. LSPosed勾选「传送门」与「安卓系统」，重启手机。不要勾选微信或QQ。新增系统观察入口要求Android13及以上，原有模块最低Android9。
3. 在「传送门增强」中打开总开关及「显示一次性捕获操作」。宿主仍限定传送门4.1.3 / 40013。
4. 返回微信中的原卡片，长按触发传送门，选择「捕获接下来打开的卡片」。无可提取链接时也尝试发布这个操作；有已识别应用卡片时放在现有结果之后。
5. 等待“已准备捕获”提示和传送门浮窗关闭，然后在15秒内点原卡片。若提示勾选安卓系统并重启，表示2.5秒握手未成功，不视为已布防。
6. 进入模块的「查看捕获结果」。如需进一步定位，可提供本次重启后的LSPosed日志；模块日志不含原网址。

| 显示结果 | 含义和后续判断 |
| --- | --- |
| 启动请求中发现网址 | 选中的启动字段含有效HTTP(S)，为后续流转实现提供真机依据；当前不显示或保存原网址 |
| 启动请求中未取得完整网址 | 已观察到已知网页组件，但白名单字段没有有效网址或载荷读取不完整，不能凭标题推断目标 |
| 未连接系统观察器 | 系统作用域、重启、命令接收或Provider握手未完成，需要对应启动日志 |
| 捕获已超时 | 窗口内没有匹配的已知启动；不能据此判定卡片不存在网址 |

关闭总开关、关闭捕获开关或点击「取消当前捕获」会取消当前事务。重新布防替换旧事务；只保留最近一份状态。

## 实现和边界

新增的作用域是`android`。微信、QQ不在作用域中，没有注入其进程、读取数据库或反射消息对象。系统侧仅挂接严格匹配的公开12参数`ActivityTaskManagerService.startActivityAsUser`入口；签名不匹配时停止安装该观察器。未布防时只检查租约状态，不读取Intent载荷。

传送门通过现有推荐模型生成特殊操作。点击后由模块Provider签发随机32字节的一次性nonce，系统命令通道受`SET_ACTIVITY_WATCHER`权限约束，并通过Provider校验此nonce。Provider仅接受当前用户且版本正确的传送门发起布防、取消；消费和报告接口只接受UID1000。这里校验的是系统UID，并非单独验证调用PID就是system_server。

租约绑定来源包、该用户下实际安装的来源UID和Android用户，15秒内仅消费首个对应组件启动。当前组件白名单为微信`WebViewUI`、`MMWebViewUI`和QQ`QQBrowserActivity`。不匹配的来源、UID、用户、组件不读取载荷、不消耗租约。全系统同时只有一个当前租约。

只检查Intent.data、`rawUrl`、`url`、`Intent.EXTRA_TEXT`以及六个已知嵌套Bundle键中的String；深度4、节点64、URL最多8条、单条最长8192字符。拒绝未知Parcelable、任意对象转换、非HTTP(S)、含凭据及控制字符的值。不调用原启动之外的Activity，不修改参数和返回值；原始`proceed()`调用恰好一次，原异常继续传播。

临时解析出的URL仅用于生成是否存在、数量和字段枚举；返回对象、日志和SharedPreferences均不包含URL、域名、聊天正文、原Intent。保存的元数据是来源包/UID/用户、时刻、固定白名单组件、结果枚举、字段标志、URL数量、是否请求结果及原启动结果。私有nonce在完成或取消后移除。取消命令受模块签名权限约束。

无法覆盖不经过此系统方法、没有显式组件、组件名称不同、使用小程序或其他内部入口的卡片。真实ROM的动态广播注册和权限授予、多用户Provider访问、启动时序及截图中原卡片的载荷仍需手机验证。若启动带结果回调，报告会标记，后续不能未经处理直接替换启动。

已能从传送门得到URL的既有路径继续使用应用名称/图标和原有Root/冰箱解冻方案。本次捕获操作使用通用操作图标，因为尚未解析出实际目标应用。短链接仍不联网展开，模块没有新增网络权限。
